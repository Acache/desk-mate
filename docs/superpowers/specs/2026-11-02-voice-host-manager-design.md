# 第 3 屏：语音与电脑管理设计稿（待用户确认）

日期：2026-11-02。此次仅设计，不修改固件，不刷机。用户已选择“语音优先”，本次修订统一英文、放大字号并纠正分页点。

## 现状与目标

- 第 2 屏是 BLE HID 媒体控制，可管理最多 3 个蓝牙配对对象。
- 第 3 屏是 Wi-Fi + 认证 WSS 语音控制，当前 VoiceConfig 只保存一台主机的身份、证书、令牌与地址提示；Mac 通过 mDNS 发布服务。
- 因此，本设计的多电脑列表、切换和多份授权保存均为新增能力。不能把蓝牙配对记录直接当成语音授权。
- 目标：始终知道指令发给谁；无需重配旧电脑即可新增电脑；网络和主机故障能够在屏幕上判断下一步。

## 两个方向

### 语音优先（用户已选定）

默认显示语音主屏。顶部目标条同时显示电脑名称、语音服务状态和管理入口。
中心保留“按住 KEY 说话”，录音时必须保留实时音量驱动的音波及大字号计时，底部保留最近结果入口。
点击目标条进入全屏电脑管理；从管理返回时恢复原语音主屏。

优势：延续现有使用习惯，日常录音不增加步骤；连接信息始终可见。
代价：管理需要点击一次，不同时展示所有电脑。

### 电脑优先（历史备选，不再继续）

默认展示当前电脑和一个其他电脑，底部显示对当前电脑说话。管理、切换更直接。
优势：经常在多台电脑间切换时更快；代价：语音录音的视觉中心被削弱，圆屏信息更密。

不建议把第 2/3 屏合成统一连接列表：媒体对象与语音执行对象可能不同，连接就绪条件也不同。

## 信息结构

第 3 屏语音主屏 → 语音电脑列表 → 电脑详情 → 改名 / 设为启动默认 / 断开 / 移除。
列表还有“添加电脑”和“Wi-Fi 网络”入口。
主屏最近结果 → 目标电脑、识别文本、执行结果、正确/不符合预期反馈。

首版建议保存 5 台语音电脑，列表每页最多 3 条，其余通过翻页或滚动选择；一次仅有 1 台活动语音目标。
容量 5 为待实现预算，不是现有硬件实测结论；证书按需加载，避免同时常驻 5 份 CA。

## 页面与状态

### 语音主屏

- 目标条：如“MacBook Pro · 语音就绪 ›”。只有经过身份认证与语音协议就绪后才显示就绪。
- 中心：按住 KEY 录音，松开发送。TALK 的触摸行为不在本轮默认改变；原型的“说话”按钮仅演示状态。
- 录音/发送/执行/查询结果中锁定目标。显示“指令目标：机器名”。此时禁止进入管理与切换，取消后待命令结算再解锁。
- 短按 PWR 请求取消并返回 Focus；长按 PWR 约 4 秒仍全局关机。
- BOOT 保留准备/确认重放；重放绑定原主机，不能把 A 上的历史指令发到 B。
- 不再只显示泛化 OFFLINE：区分 Wi-Fi 断开、主机未发现、验证失败、服务未就绪、应用未就绪。
- 断线保留指定目标，不自动换到另一台电脑。

### 电脑列表与详情

- 每行：别名、当前目标标记、默认启动标记、状态。长名截断，详情中可查看全名。
- 列表状态区分“当前 · 就绪”“在线 · 未连接”“离线”；同网可发现不等于语音可用。
- 详情提供连接/切换、连接诊断、管理操作；移除放在二级页，确认默认保留。
- 断开保留授权并暂停当前目标的自动重连；明确点击连接后恢复。
- 移除清除设备本地保存的该主机授权，断开活动会话。Mac 侧撤销设备令牌是独立操作，不能宣称本地移除已在 Mac 撤权。
- 移除当前目标后进入未选择状态，禁止自动改发其他电脑。

### 切换

空闲 → 选 B → 明示 A→B 并确认 → 连接/鉴权/能力验证 → B 就绪后提交切换。
失败保留 A 的目标记录并提示原因；原 A 的实际连接若受单会话资源影响已断开，应显示“恢复 A 中/恢复失败”，不可虚报一直在线。
切换期间不录音、不自动重发旧指令。旧连接的延迟结果按 command_id + server_id + session_generation 隔离。
重启时优先恢复明确指定的默认电脑；无默认时恢复上次目标。仅重连该身份，不自动选任意在线电脑。
第 2 屏 BLE 目标不随第 3 屏语音目标改变。

### 添加电脑

首版采用 USB 授权向导，沿用现有可信引导方式，但需要新增“追加主机配置而非覆盖”的协议与持久化实现。
设备提示：新 Mac 启动语音助手 → USB 连接 → Mac 确认添加 → 设备收到可信配置。
完成后提供“连接并设为当前”和“仅保存”。整个流程保留已有电脑配置。
主机按稳定 server_id 去重；相同主机重复添加更新原记录，名称/IP 不作为身份。
mDNS 仅用于找到已信任主机的位置，不把广播名称当授权。无线发现/一次性配对码作为后续增强，不冒充当前已支持。

### 网络与诊断

网络页显示 Wi-Fi 状态/名称，提供重连与更换网络。更换网络必须明确提示当前语音连接会中断。
配网通过现有 SoftAP/手机页面路径扩展，不在圆屏输入长密码；具体热点名称取实际固件，原型名称仅示意。
诊断分层：Wi-Fi → 主机发现 → TLS/令牌 → 语音服务 → 应用能力。
根据失败层给出“管理网络”“启动 Mac 服务”“重新授权”“检查 B 站/权限”等操作，不显示密钥、完整证书或堆栈。
首版可用执行能力按现有 Mac Bilibili R1 展示；Windows/其他应用只预留能力字段，不显示为已可用。

## 物理按键

- 主屏保持：KEY 说话、BOOT 准备/确认重放、PWR 短按取消/返回。
- 管理页：BOOT 上一项、KEY 下一项、PWR 短按确认；长按 BOOT 返回上一层。
- 打开管理时暂时移交语音 KEY 输入所有权；关闭管理后等待按键全部松开再恢复，避免一键穿透录音。
- PWR 全局长按关机优先级最高，在任何子页面可用。
- 管理页内横向滑动不切换三页主界面；明确返回关闭管理后恢复分页手势。

## 视觉与资源

沿用 480×480 黑底圆屏，蓝色表示语音目标与主要操作，琥珀色用于录音，状态必须同时有文字。
布局遵守圆形安全区；列表每屏最多 3 行，大触摸目标，更多信息进入详情。
用户已确定设备 UI 统一英文，沿用已有 Montserrat 字体资源。主操作/电脑名称使用约 20/24/28px，Talk 使用约 48px，次要提示 16px；不新增 18/32px 等当前未启用的字体。中文可内置为字库，不依赖 SD 卡，也不必逐字做图片；本轮选择英文主要节省字库 Flash、复用资源并简化排版。
管理层与语音重控件按需创建/销毁；始终为全局 PWR 浮窗预留空间。
分页使用已有固件全局顶部三点（y=24，约 2 秒后隐藏），不新增第二套分页控件。旧稿底部三点为设计错误，已经删除。管理层内不增加点状导航。
原型中电脑名、网络名、连接结果与识别文本均为演示数据，不访问真实设备。

## 录音实时音波（用户明确要求保留）

- 既有功能：FocusBiliStatus.rms 驱动 21 个按需创建的柱条。新管理界面不能以静态圆钮替代实时录音反馈。
- 新录音态：目标电脑始终可见并锁定；LISTENING + 48px 的 mm:ss 计时；中央 21 条圆角琥珀色音波；RELEASE KEY TO SEND 与 PWR: CANCEL 提示。
- 真实实现继续读取麦克风 RMS/音量包络，需对增益、噪声底和饱和做实机校准；音波不表示实时语音识别文本或真正 FFT 频谱。
- 优化建议：约 30–50ms 刷新，快速起音、约 150–200ms 平滑回落；安静时回到低幅短线，避免无输入仍随正弦大幅跳动。只改柱高/位置，不每帧创建对象或重建页面。
- 松开后停止录音音波更新，保留原有最早 840ms 的取消窗口：Ready to send + 0.8s 递减条，KEY 再按取消；取消不发送，超时后 Sending/Working。
- 保留原有 530ms 资格过滤、PWR 取消/返回与全局约 4 秒关机规则。
- 管理层退出必须等待按键释放后再恢复录音所有权；命令目标锁定持续到取消确认或结果结算。
- 原型“录音示例/安静示例”只使用预设音量数据，不申请麦克风权限；不能用原型效果宣称真实音频链路已验证。

录音版原型检查：已验证 21 条音波持续变化、安静样本全部收为低幅线、计时推进、目标入口锁定、释放后取消不发送、超时进入处理/结果、过短按压过滤，以及窄屏排版；无脚本异常。目标名称在锁定期间保持清晰可读。实机音波增益和麦克风灵敏度将在实现阶段验证。
