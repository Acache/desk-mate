# 八台蓝牙配对、单连接设计

用户已明确授权：保存八台配对信息，一次只连接和控制一台，开始设计、开发、测试。

## 目标与取舍

配对容量 8；底层同时连接上限 1；媒体控制目标 1。切换先断旧连接，等待断开完成后才广播接受新目标。新增配对期间不再临时停放旧主机连接；旧主机连接立即拒绝。开放新增窗口中旧主机仍可能抢连，真实发现速度需用户实机验收。关闭自动回连的旧主机可减少此影响。

仅增加应用数组会被 NimBLE 的三条 bond 上限截断；增加同时连接数又违背用户要求。因此使用 sketch 的 build_opt.h 强制所有 C/C++ 翻译单元加载 ble_build_config.h，先加载 SDK 再覆盖为 8 bonds、1 connection、16 CCCD 订阅记录。预编译控制器不变，源码构建的 NimBLE host 限制活动连接为一条。编译断言防止配置漏用。不修改机器上的全局库。

## 数据与兼容

蓝牙密钥继续由 NimBLE NVS 管理，不清除或自动淘汰已有 bond。应用元数据升级 v3，旧 v1/v2 固定三槽布局独立定义并迁移，保留启停、自动回连、别名、最后成功连接身份。新布局为八槽。容量满时需用户明确忘记设备。

## UI

保留英文、顶部现有三个全局页面指示点；不添加底部圆点。列表每页两台、最多四页，计数显示 Saved n / 8，明确 Prev/Next 按钮，边界不循环。蓝牙开关、自动回连、Add device 和 Back 常驻。两台设备行与导航不超过现有 32KB LVGL 池。触摸和物理按键均可到达全部八台。删除后修正页码；点选使用绘制时的稳定设备身份，防止异步列表变化选错目标。

## 验证

原生测试覆盖八槽边界、满容量、切换与旧会话隔离、固定旧数据迁移和新数据往返。LVGL8/9 测试覆盖所有页、触摸及按键、最后一台身份、删除末页、容量提示与真实 32768 字节池；检查截图。完整固件编译并验证 NimBLE 实际编译配置。遵循此前用户边界，不执行端到端测试，真实八台无线配对由用户验收。
