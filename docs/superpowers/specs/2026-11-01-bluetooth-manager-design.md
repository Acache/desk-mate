# 蓝牙主机管理设计草案

> 日期：2026-11-01。状态：用户已确认设计，2026-11-01 开发版已实现并完成首轮实机部署；跨主机实测待补。
> 已确认目标：多台电脑和手机之间切换，Desk-Mate 作为媒体遥控器。
> 本文件描述下一版行为，当前已交付能力见 [项目进展](../../STATUS.md)。

## 1. 目标与方案选择

让第二页从“等待 Mac 连接”升级为可管理的媒体控制中心：看得见当前主机，主动选择要控制的设备，添加/忘记设备，并控制是否自动重连。

| 方案 | 能力与取舍 |
|---|---|
| A：状态面板 | 显示连接、断开和重新配对；改动小，但不能可靠选择主机，不满足此次目标 |
| B：多主机管理（推荐） | 记住 3 台、同时控制 1 台；提供选择、添加、断开、忘记、改名、自动重连和连接暂停 |
| C：手机式通用蓝牙中心 | 同时增加扫描任意周边、耳机音箱等能力；超出本次媒体遥控范围，也不符合 C6 的经典蓝牙能力边界 |

采用 B。保留现有第三页语音控制与第一页计时器，媒体页仍以大按钮为主；管理界面由媒体页内打开，不增加第四个横向页面。

## 2. 已核对的事实

- 固件以 BLE HID Consumer Control 外设身份广播，由电脑/手机作为主机发起连接；当前代码没有绑定某台 Mac 的硬编码地址。
- 当前媒体就绪条件是加密完成且主机订阅媒体报告。现有两个全局布尔值没有按连接归属隔离，不适合直接扩成多主机管理。
- 本机 NimBLE-Arduino 2.5.0 及 ESP32-C6 core 3.3.8-cn 的配置上限为 3 个 bond。首版保留 3 个名额，运行时有效上限取配置容量与产品上限的较小值，不修改全局第三方库配置。
- bond 列表有稳定身份地址和地址类型，不天然包含主机的友好名称；临时随机地址不能用来标识持久设备。
- 对于已配对主机，点击“连接”表示接受该主机并等待其连接。主机蓝牙关闭、睡眠或不自动发起 HID 连接时，ESP32 无法保证唤醒它。
- ESP32-C6 支持 BLE，不支持经典蓝牙；本次不承担耳机/音箱音频传输。

参考：[Espressif 蓝牙能力表](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c6/api-guides/bt-architecture/overview.html)、[NimBLE bond API](https://h2zero.github.io/NimBLE-Arduino/class_nim_b_l_e_device.html)、[NimBLE 广播 API](https://h2zero.github.io/NimBLE-Arduino/class_nim_b_l_e_advertising.html)。库的在线文档可能是 2.5.1，具体接口以本机 2.5.0 头文件为准。

## 3. 功能范围

| 操作 | 用户得到的行为 |
|---|---|
| 已配对列表 | 显示最多 3 台、当前主机、目标主机、自动重连设置及设备详情 |
| 添加设备 | 开启 120 秒配对窗口，显示剩余时间；用户在电脑/手机蓝牙设置中选择 Desk-Mate |
| 切换主机 | 选择列表中的设备，只允许目标主机进入媒体就绪；其他旧主机不能抢回控制 |
| 断开 | 保留配对记录，进入手动断开状态；不会立即自动连回，直到用户重新选择或重新开启自动重连 |
| 忘记设备 | 确认后删除指定 bond 和对应别名；清楚提示主机端可能也需“忽略 Desk-Mate”后重新配对 |
| 设备命名 | 默认 Host 1/2/3 加身份地址后缀；支持选择常用别名或输入短英文别名，不伪造远端系统名称 |
| 自动重连 | 全局开关；开启时，启动或意外掉线后仅等待最近一次成功控制的主机 |
| 暂停蓝牙连接 | 停广播、断开现有链路、保留配对；恢复后按目标与自动重连设置工作 |

不并发控制多台主机，不展示没有可靠来源的“附近设备”“在线”“信号格”。手机、Windows 的按键效果以真实系统/播放器兼容性测试为准。

## 4. UI 与触摸交互

沿用黑底、暖白文字、浅蓝连接状态，以及当前圆屏的大触控区。保持现有英文字体，首版不增加整套中文字库。

### 4.1 媒体页

页面标题由 MAC CONTROL 改为 MEDIA。内容顺序：

1. 顶部：MEDIA 与可点击的蓝牙管理入口。
2. 中部：当前主机别名；下方独立显示 Ready / Connecting / Pairing / Disconnected / Bluetooth paused。
3. 中下部：上一曲、播放/暂停、下一曲，保持当前大按钮触控区。
4. 底部：Music / Volume 模式切换及紧凑连接提示。

主机名可以点击进入管理；没有配对时，中央显示 Pair your first device，并提供 Add device。音量/播放按钮只有在当前会话媒体就绪时可用；正在连接时不伪装成已连接。

### 4.2 管理面板草图

圆屏中心布局约束：主要内容位于 x=52..428，顶部/底部控件随圆形可视区域收窄；触摸目标至少 44px。

```text
              BLUETOOTH            Back

           On       Auto reconnect: On

       My Mac                 Connected  >
       Windows PC             Paired     >
       My Phone               Paired     >

                  + Add device
```

列表显示 Paired 表示已有配对记录，不表示此刻在线。选中设备打开详情，显示完整身份地址、当前状态及 Connect / Disconnect、Rename、Forget。正在等待目标主机时显示 Waiting for My Phone，并提供 Cancel。

面板覆盖当前媒体页并阻止横向翻页，关闭后回到原媒体模式。管理界面按需创建、关闭后释放；UI 不在每次刷新时重建列表。

### 4.3 新配对与容量满

1. 点击 Add device。已有连接时先询问是否暂时断开当前主机，确认前不影响播放控制。
2. 若已有 3 台，显示名额已满，引导选择明确要忘记的设备；不自动删除最老记录。
3. 配对窗口显示 Desk-Mate、剩余秒数、在目标主机蓝牙设置中选择设备的提示，以及 Cancel。
4. 配对成功且完成媒体报告订阅后显示就绪，并可立即设置别名。
5. 取消、超时或失败后恢复此前的连接策略；没有旧设备时回到空列表。

先沿用现有加密配对方式，不为既有 bond 强制更换安全参数。只有显式添加窗口接受新身份；窗口外仅允许已选择主机。一次只允许一个新增配对候选，成功后立即结束窗口，旧主机不能触发第二份媒体通知。首版不承诺跨系统一致的数字比较配对 UI；若后续引入该方式，必须单独完成主机兼容性与旧 bond 迁移验证。

2026-11-01 联测修订：已观察到旧 Mac 每秒多次自动重连，立即拒绝会反复消耗广播，使系统扫描错过发现窗口。新增配对期间可暂存已保存主机的底层重连，继续广播；这些连接不进入活动媒体会话，不接受媒体报告请求，也不修改目标。新设备媒体就绪、取消、超时、切换或暂停时断开所有暂存连接。产品仍同一时刻只控制一台主机；暂存数量受已保存主机数与控制器连接上限约束。

### 4.4 物理按键

媒体页原有短按与长按功能保持。管理面板打开时：BOOT 上一项、KEY 下一项、PWR 选择/确认，长按 BOOT 返回上层。对 Forget 的确认框默认选 Cancel；单次长按/松手不能穿透触发后续确认。

同一次按下归属于按下时的页面和面板层级；打开/关闭面板、翻页或删除设备后，旧按键松手不再发媒体键，也不意外执行新界面动作。触摸与按键使用同一操作入口。

## 5. 连接策略与状态

状态由蓝牙是否启用、工作模式和当前会话组成，不能用单一 connected 布尔值代表全部。

| 状态 | 行为 |
|---|---|
| PAUSED | 不广播、不接受连接；保留 Wi-Fi、语音服务与配对信息 |
| IDLE | 蓝牙管理可用；未选择主机或自动重连关闭，不等待旧主机自动接管 |
| WAITING | 面向目标主机开放重连，最多 30 秒显示主动等待进度 |
| BACKGROUND | 自动重连开启时，本次 30 秒等待结束后仅低频广播给所选主机；无连接进度或忙碌弹层，允许其他页面正常使用 |
| CONNECTING | 已建立链路，进行加密和订阅准备；媒体键仍不可用 |
| READY | 目标会话已加密、媒体报告已订阅；允许发送 HID |
| PAIRING | 显式添加窗口，最多 120 秒；只接纳一个新候选 |
| ERROR | 展示可操作失败信息，允许重试/取消/重新配对，不永久卡住 |

### 5.1 切换事务

- 用户从 A 切到 B：先禁止新媒体按键并发送 A 的松键报告，停止旧广播，断开 A，再按 B 的身份设置过滤和连接等待。
- 广播配置必须在停止广播后修改。不能保留 advertiseOnDisconnect(true) 造成的无条件开放广播；重连策略由管理器控制。
- 新连接身份解析和加密确认前保持门控；非 B 主机被拒绝，不因其旧回调覆盖 B 的会话状态。
- 30 秒未就绪：结束本次界面进度，显示目标未连接；保留 B 的选择，提供 Retry / Back。自动重连关闭时停止广播并回 IDLE；开启时进入 BACKGROUND，使用约 1000ms 间隔的目标过滤广播。Back 恢复上次目标并按设置等待它重新连接，不承诺瞬间恢复。
- 用户确认切换后不自动换回其他主机；避免连接方向与用户选择相反。

### 5.2 开机与掉线

- 启动时导入既有 NimBLE bond；已配对 Mac 不需因为升级而被删除或重新配对。
- 自动重连开启：启动时只等待最近成功 READY 的主机；当前运行中尊重用户新选择。意外掉线/广播启动失败以 1/2/4/8/16/30 秒有界退避恢复目标广播，成功 READY 后重置退避；不会自动改连列表中的其他设备。
- 自动重连关闭：开机和意外断开后回 IDLE，用户点选设备才能重连。设置关闭时不主动断开当前 READY 会话。
- 手动 Disconnect 在当前运行期间抑制重连；若自动重连开启，下一次重新启动仍按持久化目标恢复。UI 明确区分临时断开和持久化暂停。
- 暂停设置持久化；恢复不擦除 bond，也不重建 Wi-Fi 或语音配对。
- WAITING 的 30 秒进度结束后严格按 IDLE/BACKGROUND 分支处理；不做主机扫描，不循环阻塞。BACKGROUND 可由 Disable auto reconnect / Disconnect / Pause / 选择其他设备退出。

### 5.3 隐私地址与主机名称

2026-11-02：完成配对后异步尝试读取对端 GAP Device Name；不保证主机开放该属性。读不到或现有字体不能显示时，直接提供快捷名称和自定义英文名；用户别名优先于后续自动读取。元数据 v2 保留名称来源并迁移 v1 别名。

以地址类型和已解析身份地址作为持久键，不能保存临时 RPA 作为新设备。利用 NimBLE identity/bond 信息恢复同一主机；发现未解析身份时暂不写入独立槽位。

主机通常不作为可扫描的 HID 服务端广播，因此不通过扫描结果伪造手机式附近主机列表。新增主机从其系统蓝牙设置发起，已有主机在 Desk-Mate 上选中。

首版重连优先使用已解析身份的过滤广播；隐私地址设备必须实测白名单与地址解析是否正确协作。不提供静默降级成任意主机接管的路径；遇到平台限制时显示在主机蓝牙设置中点连接的提示。

## 6. 后端结构与持久化

- 将蓝牙生命周期与 HID 报告逻辑移到独立管理模块，Arduino 主程序保留现有 media_begin / media_poll / media_send 的兼容入口或薄适配。
- 纯状态模型与 Arduino/NimBLE 解耦，用原生测试覆盖策略和竞态；UI 通过固定大小快照和操作枚举交互。
- NimBLE 回调只投递有界事件；不调用 LVGL，不写 NVS，不等待用户操作。管理器在独立于 LVGL 锁的主循环阶段处理广播、断开、配对和持久化。
- 当前会话保存连接 handle 和本地 generation；subscribe、auth、disconnect 事件与其匹配，旧连接的迟到事件不能清除新会话。
- HID notify 显式发送到当前连接，不能沿用可能广播到多个连接的默认发送方式。旧会话的按下/松开不得跨会话重放。
- 无活动链路时本地清理未完成松键；链路仍在时有界重试松键。切换失败不向新主机补发旧命令。
- 非配对窗口拒绝额外链路；新增窗口按联测修订暂存已保存主机的重连，并且不能进入可接收媒体报告状态。有效容量受当前控制器连接配置约束。

NimBLE 自身存储 bond 和密钥，应用只在独立 Preferences namespace 存储版本、启用开关、自动重连开关、选择目标、最近成功目标、每台主机短别名。别名最多 20 个可显示 ASCII 字符，按需出现编辑器，关闭时释放。无需手工复制密钥。

启动时将元数据与实际 bond 对账：导入旧 bond、删除无对应 bond 的条目、修正失效目标。操作持久化必须检查结果；不得在 UI 显示“已忘记”但底层删除失败。NVS 失败不循环写入。

当前库默认 bond 存储溢出处理可能删除最老主机。本次必须在容量满时阻断新增配对，并检查溢出策略是否仍可能因并发/CCCD 存储触发删除；如需修改 store callback，应使用应用可配置接口/本地适配，而不改用户全局库源码。

## 7. 实现与交付顺序

这是审阅用实施轮廓，批准后另写可执行计划。

1. 纯状态模型与原生测试：目标选择、配对窗口、容量、手动断开、暂停、超时、旧事件与会话隔离。
2. NimBLE 管理器与持久化：导入现有配对，按主机发 HID，受控广播与真实失败回报。
3. 媒体页与管理面板：独立快照接口，设备列表、详情、新配对与按键路由；LVGL 8/9 截图与交互测试。
4. 全固件编译、内存验证，再用真实多主机完成配对、切换和异常回归，维护验收记录。

预期修改范围：media_ble.h（拆分/薄适配）、新增 src/media_ble/ 模块、focus_ui.h 与管理面板 UI 模块、desk-mate-app.ino 的输入和轮询桥接、原生测试、LVGL 模拟器、按键/操作文档。Voice 协议和主机端语义执行不因 BLE 切换而自动更换目标。

## 8. 验收标准

- 原 Mac 配对记录迁移后可重连，原有六种媒体/音量动作继续正常。
- A/B 两台主机均在附近时可选择 B，A 的自动重连不能接管媒体键；只有 B 收到按键。
- 第三台可保存；第四台添加需用户明确忘记一台，不静默淘汰。
- 手动断开不立刻连回；暂停与自动重连设置跨重启符合上述规则。
- 新配对窗口成功、取消、到期、拒绝/错误均能恢复可操作状态。
- 忘记当前主机、主机端先忽略、隐私地址变化、重启后列表恢复都有实机记录。
- 断线发生在按键按下/松开之间，不出现卡键或命令发到新主机；非当前 handle 回调不破坏现有 READY。
- 管理面板内点击/滚动/按键不穿透到底层媒体页；关闭后原按键语义恢复。
- LVGL 8/9 均通过界面测试并检查圆屏裁切。32KiB 硬件 LVGL 池保持不变，管理面板反复开关不泄漏；记录固件堆峰值、TLS 握手阶段及语音录音中的最小空闲内存，不能只用截图版的扩容池判定通过。
- 计时器、B 站语音 R1、BLE+Wi-Fi 并存工作正常。BLE 主机切换不等于将 B 站语音服务切到手机。
- 实机优先用当前 Mac 与另一台电脑/手机完成切换；无法实际接触的平台明确标“未验证”，不以模拟器宣称跨平台兼容。

## 实现补充

为满足 32KiB LVGL 池约束，管理面板打开时释放媒体页控件，关闭时重建；反馈控件和语音波形也按显示需要创建/释放。圆形遮罩缓存限制为两项，并关闭未使用的默认主题；通过模拟器检查现有视觉与交互。
