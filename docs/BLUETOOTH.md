# 蓝牙连接管理

> 2026-11-02 开发版。Desk-Mate 作为 BLE 媒体遥控器，最多记住 8 台电脑/手机，同一时刻只连接和控制 1 台。支持情况以文末验证记录为准。

## 开始使用

在第二页点击 **BLUETOOTH / manage** 或中央主机名打开管理面板。原来的上一曲、播放/暂停、下一曲与 Music/Volume 切换仍保留。

| 入口 | 功能 |
|---|---|
| Bluetooth ON / PAUSED | 暂停或恢复广播和连接，保留配对；暂停设置跨重启保留 |
| Auto reconnect ON / OFF | 是否在启动或意外断线后等待上次成功连接的主机；关闭不会主动断开正在使用的主机 |
| 已配对主机行 | 打开详情，连接、断开、改名、忘记 |
| + Add device | 开启 120 秒新增配对窗口；若已连接先确认断开当前主机 |

设备列表每页两台，最多四页；Saved 显示已保存数量与八台上限，Page 显示当前页码。Prev / Next 翻页，也可用 BOOT/KEY 选中翻页按钮、PWR 确认；不可用的翻页按钮会变暗并被物理导航跳过。管理页不增加分页圆点。

## 添加与切换

1. 点击 Add device，在目标电脑或手机的系统蓝牙设置中选择 **Desk-Mate**。
2. 身份已解析、底层配对记录已保存、加密和媒体订阅都完成后，设备加入列表。对端允许时会异步读取设备名；不能读取或名称超出现有字体时，直接提供 Mac、Windows PC、iPhone、Android phone、Harmony phone 或 Custom name 的快捷命名。
3. 切换时，在 Desk-Mate 列表里选另一台，点击 Connect / retry。它会断开当前连接，只接受目标主机。
4. 如果目标没有自行连接，请在目标系统的蓝牙设置中点击 Desk-Mate。外设无法强制唤醒睡眠或已关闭蓝牙的主机。

每次主动 Add device 都开启新的 120 秒窗口；启动广播时显示 Starting discovery，连接过程中显示 Securing connection。已配对不等于在线。详情的 Device name 可再次选择快捷名称或输入最多 20 字符的英文别名；用户设置的名称不会被后续自动读取覆盖。设备不公开名称时，以 Device 加身份尾号暂作区分，不伪造系统名称。

新增窗口内只接受未保存的新设备；旧主机自动抢连会立即断开，不再停放临时连接。广播会在断开完成后恢复。如果旧主机持续抢连影响发现，可以临时关闭旧主机蓝牙，再在新设备上搜索 Desk-Mate。切换设备也必须先断开旧连接，才接受选定的新主机。

## 断开、重连与忘记

- Disconnect 是本次运行内的手动断开，不会立即连回；可以再次点击 Connect。如果自动重连开启，重启后仍会尝试上次成功主机。
- 自动连接超过 30 秒还未就绪时，结束进度；自动重连开启则在后台低频等待目标，否则停止等待。不会自动改连其他主机。
- Forget this device 需要再确认；界面默认选 Cancel。忘记非当前设备不会中断当前主机。
- 本地忘记后，目标主机可能仍留有旧密钥；重新配对前，在目标系统中也“忽略/移除 Desk-Mate”。
- 八个名额满后，先选择明确要忘记的设备，再添加。不会自动淘汰最早配对。
- 从原三台版本升级时，保留底层配对密钥、已有别名、蓝牙开关、自动重连开关和最后成功连接目标；不需要为了扩容清空配对。

## 三个物理按键

管理面板内，BOOT 上一项、KEY 下一项、PWR 选择；长按 BOOT 返回。改名键盘内 BOOT/KEY 选择字符键，PWR 输入，勾选键保存；也可触摸键盘。管理面板关闭后恢复原媒体按键功能。

## 与 B 站语音的关系

蓝牙连接只决定媒体键发给哪台主机。第三页语音仍通过 Wi-Fi 连接已配置的主机服务；切换到手机不会自动将 B 站语音执行目标切到手机。计时器、Wi-Fi 配对与语音凭据独立保留。

## 开发诊断

`firmware/desk-mate-app/build_opt.h` 强制为 sketch 和库的所有 C/C++ 编译单元加载 `ble_build_config.h`。该头先读取 SDK 配置，再统一设置 NimBLE 保存 8 条 bond、最多 1 条连接、32 条 CCCD（预留八台的 HID、电池、服务变更和语音通知）。仅用 `-D` 会被当前 ESP32 SDK 配置覆盖；不要只改应用数组或机器上的全局 NimBLE 库。`ble_manager.cpp` 编译断言检查配置，固件需完整重新编译。

共用连接的语音传输目前处于实验阶段，见 [BLE 数据实验与对端桥接方案](BLE_VOICE_LAB.md)。正常第 3 屏仍走 Wi-Fi/WSS，不能把配对成功等同于 BLE 语音已经可用。

串口 `BLE: radio` 记录控制器广播是否 active、实际连接数、当前会话句柄和剩余配对时间。`advertising ... packet=` 是本地广播数据，须结合外部扫描确认可发现性。

需要自动复现时，编译增加 `--build-property compiler.cpp.extra_flags=-DDESKMATE_BLE_DIAGNOSTICS`。该调试版本接受 USB 串口行命令 `ble pair`、`ble cancel`、`ble disconnect`、`ble connect 0`（从 0 开始的列表索引），通过既有 provisioning 单一串口读取任务将请求交给蓝牙队列，并周期性检查堆完整性。普通编译不接受这些调试命令。调试期间保持串口打开，避免 USB 打开/关闭触发 ESP32-C6 重启。
