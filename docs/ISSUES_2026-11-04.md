## 1. App 本身（UI）

### UI-1 菜单栏「箭头」多一步
- 现象：顶部只有一个「»」箭头，点开才能看到 Desk-Mate 的菜单。
- 代码：`mac/app/DeskMate.swift:62` `NSStatusBar.system.statusItem(withLength: .variableLength)`，`:63` 用**长文字** `"Desk-Mate · 启动中"` 作为标题。
- 根因：状态项宽度是长文字，菜单栏拥挤时被系统折叠进溢出区（就是那个箭头）。
- 修复方向：改用**短图标**（template image，16×16 或 SF Symbol），标题置空或极短；点图标直接弹菜单。启动/停止/连接阶段用图标角标或第二个小图标表达，而不是往标题塞文字。

### UI-2 权限跳转不直达
- 现象：点「权限」只打开「安全性与隐私」总页，有的能直接加，有的还要自己找。
- 代码：`DeskMate.swift:351` 打开 `x-apple.systempreferences:com.apple.preference.security`（只有总页）。
- 修复方向：按权限分别打开子页（本机为 **macOS 27.0.1**，需用新版锚点并在本机实测）：
  - 辅助功能 `?Privacy_Accessibility`
  - 屏幕录制 `?Privacy_ScreenCapture`
  - 蓝牙 `?Privacy_Bluetooth`
  - 麦克风 `?Privacy_Microphone`
  - macOS 13+ 新锚点：`com.apple.settings.PrivacySecurity.extension?Privacy_Accessibility`；
  - macOS 27 上建议直接测新锚点，旧锚点作为回退；四个权限分别对应 `Privacy_Accessibility / Privacy_ScreenCapture / Privacy_Bluetooth / Privacy_Microphone`。
- 说明：**可以实现**，但系统版本间锚点不同，需要一次真机验证；个别权限（如蓝牙）系统只允许在总页勾选，属系统限制。

### UI-3 只有菜单，没有 UI
- 现象：所有操作都在 NSMenu 里，配置/诊断/状态不直观。
- 修复方向：加一个 SwiftUI/AppKit **主窗口**：状态（服务/BLE/STT/模型/B站 CDP）、设备切换、权限检查清单、一键诊断导出、日志查看；菜单只保留「打开主窗口 / 服务启停 / 退出」。菜单结构可保留作为快捷方式，但不再是唯一入口。

## 2. 指令问题（有数据库证据）

### CMD-1 搜索词带标点 → 0 卡片 → UNKNOWN
证据（`action_steps`）：
```
搜索猫咪。   query="猫咪。"    ui_cards:0 → OUTCOME_UNKNOWN
搜索猫咪.    query="猫咪."     ui_cards:0 → OUTCOME_UNKNOWN
搜索小猫咪。 query="小猫咪。"  ui_cards:0 → OUTCOME_UNKNOWN
```
根因：`intent.py:221-223` 的**字面规则**优先于归一化规则：
```python
search_only = re.fullmatch(r"(?:请|麻烦|帮我)?(?:搜索|搜)(.+)", literal)
return _ok([("bilibili.search", {"query": search_only.group(1).strip()}, [])])
```
`literal` 是原始文本，`.strip()` 只去空白，**保留「。」**。B 站搜索带句号查不到结果 → `ui_cards:0` → 适配器判 OUTCOME_UNKNOWN。
修复：查询前统一 `strip("，。,.!！?？、;；:： ")`；或直接用 `normalize_intent_text` 后去掉首尾标点；同时把 `query` 送 B 站前做一次标点清理兜底。

### CMD-2 搜索失败后「播放第 N 个」全部失效
证据：
```
播放第一个视频。 → CLARIFY_NEEDED 「请先搜索一个视频，再说第几个」
播放第二个视频。 → 同上
打开第4个。     → 同上
```
根因：搜索返回 OUTCOME_UNKNOWN（0 卡片），数据库没有写入 search 快照；`rule_based_proposal` 的序号规则要求 `context.search_snapshot` 且未过期，否则 CLARIFY。
修复：CMD-1 修好后快照自然产生；另外建议序号规则在**当前页面就是搜索结果页**时，允许从页面实时读取结果（见 CTX-2），不要只依赖数据库快照。

### CMD-3 点赞 → TARGET_STALE（没有当前视频）
证据：
```
点个赞。             → FAILED TARGET_STALE「没有可用的当前视频」
给这个视频点个赞。   → 同上
```
根因：`pipeline.py:342` 的刷新条件是关键词列表
```
"暂停","继续","恢复","点赞","投币","收藏","弹幕","评论","快进","后退","上一集","下一集","上集","下集"
```
「点个赞」「给这个视频点个赞」**不含「点赞」子串**（是「点个赞」），所以没有刷新播放器快照；planner 的 like 绑定要求 `player_snapshot` → TARGET_STALE。
修复：刷新条件改为按**意图动作**判断（`proposal` 里出现 like/favorite/danmaku/next/prev/seek/comments 就刷新），不要靠中文关键词匹配；或把「点个赞」「赞」等别名加进列表。

### CMD-4 点赞/收藏/弹幕被 page_exit 取消
证据：
```
点赞。          → CANCELED USER_CANCELED "canceled: page_exit"
收藏。          → CANCELED USER_CANCELED "canceled: page_exit"
发个弹幕说的好。 → PENDING，text="说的好。"，随后 canceled page_exit
```
含义：设备在命令处理中向主机发了 `cancel(reason=page_exit)`。需要确认是用户当时切页/按键，还是固件误判（例如滑页、PWR、页面重建）。**待复现**：串口日志能看到 `VOICE: fsm ... state=` 与取消原因。
影响：用户会感觉「点赞没反应/被吞」。

### CMD-5 词表外命令 + STT 误听「上一P」（OUT_OF_SCOPE → NOT A BILIBILI COMMAND）
证据（全部 `OUT_OF_SCOPE`）：
```
关闭。 / 关闭这个视频。 / 关掉这个视频。
静音。
回到主界面。
上一个视频。 / 下一个视频。 / 回到上一视频。 / 上一个。 / 下一个。
上一批。 / 下一批。   ← 用户实际说的是「上一P / 下一P」，STT 把 P 听成了「批」
点开第四个视频。 / 点开14秒那个小猫咪的视频。
```
根因：
- `_KEYWORDS` 只有 `打开/搜索/搜/播放/暂停/继续/恢复/点击/停/点赞/投币/收藏/弹幕/评论/快进/后退/回退/倒退/音量/声音/下一集/下集/上一集/上集/币/小声/大声/接着播/接着放/往后/往前/收起来/太吵/跳到/点个赞/b站/哔哩哔哩`，**没有** 关闭/关掉/静音/回主页/上一个视频/下一个视频/点开/观看/上一批/下一批。
- 「关闭/关掉」没有对应动作（现有只有 `bilibili.comments` 的开关，没有「关闭播放器/退出视频」）。
- 「回到主界面」也没有用户可用的 action（适配器内部 `_home()` 只用于搜索兜底）。
- 「上一个/下一个视频」与「上一集/下一集」不同词，未做同义归一。
- **STT 同音误听**：「上一P/下一P」被识别成「上一批/下一批」。需要在归一化层加实体别名（批→P、上批/下批、上一p/下一p），并把「上一P」纳入多P切换意图——这属于识别层，不是词表能解决的。
修复：补词表与同义归一；明确「关闭」的语义（暂停？退出播放器？回到搜索页？）；新增 `bilibili.home` 或复用 `_home`。

### CMD-6 进度跳转 OUTCOME_UNKNOWN
证据：
```
跳到第15分钟。 → bilibili.seek target_s=900 → OUTCOME_UNKNOWN（无 output/evidence）
跳到第30秒。   → bilibili.seek target_s=30  → OUTCOME_UNKNOWN
```
根因待复现：`execute_ms=2`，说明动作层立即失败（很可能当时播放器页不可用 / CDP 不可达 / 没有 video 元素）。需要下一次复现时抓 `player_ui` 的返回。
注意：用户主观上认为「进度跳转基本正常」，可能指其它几条成功；这两条确实失败。

### CMD-7 弹幕文本带标点
证据：`发个弹幕说的好。` → `text="说的好。"`（同样来自 `intent.py:214-219` 的 literal 规则）。
修复：与 CMD-1 相同，发送前清理标点（或保留标点但只去句末标点）。

### CMD-8 搜索成功也不显示 DONE
现象/证据：所有搜索命令要么 OUTCOME_UNKNOWN（0 卡片），要么没有成功样本；即使有结果，用户描述「搜完显示 unknown 而不是 done」。
根因：适配器只有拿到 `ui_cards>0` 才判成功；目前搜索路径在打包版下几乎必失败（CMD-1）。
修复：CMD-1 修复后验证；同时给搜索增加「结果页 URL/标题变化」作为弱成功判据，避免 0 卡片时直接 UNKNOWN（至少要给出可诊断的失败原因，如 `NO RESULTS`）。

## 3. 状态与上下文（设计层）

### 3.0 用户确认的语义（2026-11-04 追加）

- **关闭/关掉这个视频** = 关闭当前视频，回到主界面。
- **上一P/下一P** = 多P切换（不是「上一批」）。
- **「第 N 个」按当前界面解析**：
  - 搜索结果页 → 搜索结果列表的第 N 个；
  - 播放页 → 右侧推荐/合集列表的第 N 个（需要区分「合集节目列表」与「推荐视频」）。
- **「下一集」在播放页**：优先下一集/下一P；没有下一集时，落到推荐列表的下一个。
- **搜索结果页可能先出现影视剧/UP 主推荐块，再是真正的结果列表**：解析时必须跳过推荐块，只取结果容器。
- 语言不可枚举 → **上下文 + 模型 + 反馈学习**是主方向；规则只覆盖高频确定指令。

### 3.1 上下文快照（建议每次指令前由 CDP 采集）

```json
{
  "page": "search|player|home|other",
  "main_route": "#/page/search-page",
  "player_open": true,
  "search": {"keyword": "猫咪", "result_count": 62,
             "results": [{"i":1,"title":"…","bvid":"BV…","duration":"12:34","author":"…"}],
             "skipped_recommend_blocks": 2},
  "player": {"bvid":"BV…","title":"…","p":2,"parts":12,
             "episodes":[{"i":1,"title":"…","bvid":"BV…"}],
             "recommendations":[{"i":1,"title":"…","bvid":"BV…"}]}
}
```
- 采集方式：`cdp_player` 连接主窗口与播放页两个 target，读 DOM（结果容器、条目、列表），**不依赖上一条命令的状态**。
- 规则/模型拿到的是「当前界面事实」，不是「上一次搜索结果」；数据库快照只做缓存。

### 3.2 指令解析分层

1. **精确快路径（规则，0 模型开销）**：播放/暂停/音量/点赞/投币/收藏/静音/关闭/回主页，以及上下文明确的「上一集/下一集/上一P/下一P」。
2. **上下文规则**：第 N 个、下一个、这个视频——按 `page` 与列表内容做确定性映射；映射不唯一时交给模型。
3. **模型兜底**：长句、指代（「14 秒那个」）、多动作、搜索结果页带推荐块等，把 `context` + transcript + 允许动作交给 Ollama；接受更高延迟。
4. **反馈学习**：记录 (context, transcript, action, GOOD/BAD)；个人分类器/检索样例逐步覆盖高频场景，让复杂指令也走快路径。

### CTX-1 指令之间强绑定
用户明确要求：**每条指令无状态**，不能因为上一次搜索失败就导致后续「播放第 N 个」不可用。
现状：planner 依赖数据库 `search_snapshot`，而快照只在搜索成功时写入；失败一次，整条链路失效。
方向：决策时读取**当前界面上下文**（当前 URL/页面类型/结果卡片数/播放器状态），而不是依赖上一条命令的产物；快照只作为加速缓存。

### CTX-2 决策没有利用上下文
现状：规则只看文本；模型提示词里的上下文有限（ChatGPT 版加了部分快照）。
方向：
- 规则引擎先做**精确匹配**（播放/暂停/点赞这类高频明确指令）→ 立即执行，零模型开销；
- 复杂/长句/带指代（「第 14 秒那个」「第二个」）→ 把**上下文（页面类型、结果列表前 N 条标题/时长/bvid、当前视频）**拼进模型提示，让模型决策；
- 结果回写快照，供后续指令使用（但**不作为唯一来源**）。

### CTX-3 规则/模型边界不清
证据：同一会话里「搜索猫咪」走 rules，「跳到第15分钟」走 ollama（`route=ollama decision_ms=530`）。
方向：明确「命中确定性语法就走规则并直接执行；规则不命中才升级到模型」，并在日志里记录 `route` 与命中原因，便于离线评估。

## 4. 性能与稳定性

### PERF-1 打包版搜索慢
证据：`execute_ms` = 5025 / 3275 / 3208 / 3284（开发版实测约 2400）。
方向：先修 CMD-1；再对比打包版 AX 搜索与开发版差异（打包版可能每次新起 ax_helper 进程、或搜索等待策略不同）。

### PERF-2 暂停慢
证据：`refresh_ms=1307 + execute_ms=1896`。
方向：暂停前刷新播放器快照 1.3s 可以缩短（只读一次 CDP `video.paused`），或直接让 CDP 判定并执行，不走 AX 往返。

### PERF-3 BLE/网络噪声
证据：23:36、23:39 `BLE companion (authenticating): TimeoutError`；zeroconf 多次 `No route to host`。
方向：认证超时重试策略与日志；zeroconf 在无网络路由时静默降级（或仅在启用发现时启动）。
