# USB 授权与日常连接

USB 授权用于让 ESP32 信任当前服务端，保存设备身份、凭据和服务端信任信息。凭据持久保存，没有定期重做授权的要求。

## 什么时候需要

- 新 ESP32 首次关联这台服务端，或新增另一台电脑。
- 设备恢复出厂、擦除了授权存储或删除了该语音电脑。
- 服务端配对数据被清除、撤销或身份重新生成。
- 确认凭据不匹配，需要主动替换当前电脑的授权。

普通启动、App 更新、macOS 权限重检、蓝牙断线重连、Wi-Fi 配网，以及保留 NVS 的普通固件更新，不需要 USB 重新授权。

## 服务端入口

- **选择设备**：选择蓝牙语音输入。
- **重新连接**：仅重建当前蓝牙语音连接，保留授权，不停止服务、STT 或模型。
- **添加设备…**：首次通过 USB 建立授权；已有本机 USB 注册记录且凭据未撤销时，直接显示已有记录，不打开串口或生成新密钥。
- **诊断与高级设置 → 重新授权（USB）…**：明确更换这块设备上当前电脑的凭据。其他电脑授权、Wi-Fi 和蓝牙配对保留。

“已有本机授权记录”仅说明服务端保存过记录。只有当前蓝牙双向认证通过，界面才显示“授权已验证”。超时、离线或未选中 Mac 显示“授权待连接确认”，不会自动要求重做 USB 授权。

旧版本没有记录 USB 硬件身份，不能安全地把任意在线蓝牙板与 USB 插入的另一块板混为一谈。首次建立新记录后，后续重复添加可直接复用；端口号变化不影响同一块板的身份识别。没有可靠硬件序号的串口不会被猜测为已授权。

## 这次修复的复位原因

实板复现中，原 pySerial 打开流程在发送任何授权数据前就出现 `rst:0x15 (USB_UART_HPSYS)`，随后重新启动并重建连接。提前设置 DTR=false、RTS=false 仍会在打开时分两次写控制线。

对照测试确认，单纯 POSIX `os.open` 和关闭端口不会复位；同时更新 DTR/RTS 后，实板打开、`VA_SETUP` 握手、关闭均保持认证，无启动重刷。实现参考 [Espressif 原子串口控制](https://github.com/espressif/esp-pylib/blob/master/esp_pylib/serial_reset.py)。

生产授权和诊断使用 `voice_assistant.usb_serial.open_provisioning_port()`。没有关闭或修改全局 USB 复位机制，原有刷机机制和蓝牙自动重连偏好保留。直接使用旧的普通 pySerial 诊断脚本仍可能触发复位。

完整换凭据联测还修复了语音会话的刷新：服务端在空闲时检测固件 epoch 变化并安静重建认证，录音时跳过该 STATUS 读取；固件仅在通知订阅开启或物理连接代数改变时建立新会话，同一连接的重复订阅不会打断正在组装的帧。因此 USB 换凭据后可以更新认证，而不必重启整块设备或手动重选蓝牙。

对于历史 peer 绑定指向旧服务端的情况，明确 USB 授权会记录当前配置的一次性绑定迁移许可。只有该配置完成 HMAC 双向认证后才更新当前 peer 绑定并消费许可；失败认证不消费许可，旧配置也不能凭历史记录覆盖其他绑定。添加另一台电脑不会提前改正在使用的绑定。没有清空其他电脑、Wi-Fi 或蓝牙配对来绕过校验。

## 本机记录与故障处理

USB 硬件标识的哈希、服务端 ID 和设备 ID 保存在私有应用数据库的 `usb_registrations` 表，与新凭据及旧凭据撤销在同一事务中提交。不会保存明文 token 或 USB 硬件序号。数据库 v2 → v3 升级保留原有表和数据。

设备 ACK 后若数据库保存失败，界面会明确提示“设备已接收新凭据，但本机授权记录保存失败”；先修复存储，再到高级设置重新授权。不要反复点击添加设备。仅诊断摘要文件保存失败时，授权仍视为已成功持久化，不会诱导重复换密钥。

硬件验收脚本：`mac/scripts/verify_usb_authorization.py`。默认只检查状态；显式 `--authorize` 才写入授权，`--replace` 追加明确替换测试，`--reconnect` 测试真实重连。必须选定正确的 USB 板并保持唤醒。

## 已完成的验证

2026-11-05，正式发布 **0.3.2 build 14** 与更新后的固件已在同一块 ESP32-C6 和本机 Mac 完成真实 USB 重授、两次重复添加、定向替换及日常重连。USB 操作无设备复位或物理蓝牙连接重建；重复添加无串口操作或凭据变化；重连建立新会话，服务、STT 和模型进程保持。关闭诊断串口后的两次新健康快照仍保持认证。

正式原生 UI 的普通“添加设备”也已验证显示“已有本机授权记录 · 未打开 USB 或更换凭据”，连接和两项 macOS 权限保持正常。284 项单元、8 项协议集成、6 项 native 测试通过。详见 [完整验证记录](USB_AUTHORIZATION_VALIDATION_2026-11-05.md)。

现场测试范围为本机与单板；其他 profile 的保存由数据比对和原生测试覆盖，尚未实际切换第二台电脑或执行完整 Wi-Fi 配网流程。
